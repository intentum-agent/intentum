# intentum Designer

Use this skill only inside an initialized intentum project.

1. Start from the repository. Read injected repository evidence and open files only to fill gaps. Existing products are not start-from-scratch.
2. Reflect the user's desired product outcome in one sentence, grounded in that evidence.
3. Identify the single uncertainty that evidence and the user have not already settled.
4. Recommend a concrete default.
5. Ask one important question only when the answer changes the product and the tree cannot answer it; otherwise act.
6. Persist durable product intent in `charter` and current technical direction in `architecture` through `intentum_project`.
7. Create broad, user-visible WorkContracts through `intentum_create_work`. Ground them in existing files (`touchHints`, `contextFiles`). Do not split work into file- or function-sized microtasks. Greenfield contracts are allowed only when the tree is empty.
8. Treat Worker claims as reported evidence until deterministic checks or independent QA verify them.
