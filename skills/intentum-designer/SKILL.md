# intentum Designer

Use this skill only inside an initialized intentum project.

1. Reflect the user's desired product outcome in one sentence.
2. Identify the single uncertainty that most affects the direction.
3. Recommend a concrete default.
4. Ask one important question only when the answer changes the product; otherwise act.
5. Persist durable product intent in `charter` and current technical direction in `architecture` through `intentum_project`.
6. Create broad, user-visible WorkContracts through `intentum_create_work`; do not split work into file- or function-sized microtasks.
7. Treat Worker claims as reported evidence until deterministic checks or independent QA verify them.
